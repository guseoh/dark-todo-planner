# Todo Planner 전체 기능·UI/UX 검토

2026-11-12 · 현재 작업 브랜치의 화면 진입점과 구현 기준. 배포 화면의 실사용 관찰이나 사용성 테스트 결과는 포함하지 않는다. 개선 범위는 데스크톱이며 기존 모바일 동작을 회귀 확인한다.

## 화면의 역할

| 화면 | 현재 코드에서 확인한 기능 | 개선 제안 |
| --- | --- | --- |
| 오늘 | 빠른 입력, 집중 작업, 진행률, `계획하기`의 후보·지난 일정 | 진입 직후 입력·집중·오늘 목록을 읽을 수 있게 둔다. 지난 예정일은 개수와 `검토`로 표시하고, 마감 초과는 행에서 별도로 보여준다. 후보에서 오늘로 가져온 Task는 바로 목록에서 찾을 수 있게 한다. |
| 전체 Todo | 검색, 필터, 다중 선택, 일괄 변경 | 검색·필터를 한 줄로 모으고 적용된 조건·결과 수·초기화를 보인다. 선택 도구는 선택 중에만 표시한다. `현재 결과 전체 선택` 범위와 부분 실패를 명시한다. 프로젝트에서 건너오면 해당 프로젝트로 필터링한다. |
| 프로젝트 | 프로젝트 탭, 칸반·목록, 검색·마일스톤 필터 | 일정과 Task를 단일 칸반에서 관리한다. 보드 위에서 Task를 검색하고, 카드의 `⋯`에서 제외·휴지통 이동을 실행한다. [칸반 상세 설계](project-workspace-redesign.md) |
| 캘린더 | 한 메뉴에서 월간·주간 전환, 날짜별 Todo·목표 | 월간은 훑어보기, 주간은 배치·조정에 집중한다. 이전·오늘·다음과 월간·주간 전환의 위치를 맞춘다. 보기 전환 시 선택 날짜를 유지하고, 날짜 변경은 예정일에 적용한다. |
| 메모 | 검색, 고정, 읽기·편집, Todo·프로젝트 연결, 초안 | 목록과 읽기 영역의 선택을 유지한다. 저장 성공·초안 보존·실패를 구분한다. Task로 전환한 뒤 원본 메모와 새 Task를 서로 찾을 수 있게 한다. |
| 낙서장 | 자동 저장, 로컬 복구, Markdown·서식 편집, 찾기·바꾸기 | 본문 너비와 도구 위치를 안정화한다. 편집 중에는 저장 상태를 한곳에서 보여준다. 원본 모드를 바꿀 때 문서 위치와 초안을 보존한다. |
| 개발 활동 | GitHub 기여와 Codex 작업 기록 | 출처별 로딩·연결 오류·빈 상태를 구분한다. 실패한 출처만 다시 불러올 수 있게 한다. 작업 화면에서 보이지 않는 현재 정보 구조를 유지한다. |
| 설정 | 테마, 앱·연결 정보, 루틴, 자동화·Discord, 데이터·백업 | 테마·루틴처럼 자주 쓰는 항목을 쉽게 찾도록 탭 이름과 위치를 맞춘다. 백업 다운로드·복원·영구 삭제는 영향을 받는 범위를 클릭 전에 보여준다. |
| 휴지통 | 검색, 복원 미리보기, 복원·영구 삭제 | 원래 프로젝트·날짜와 복원 불가 연결을 미리보기에서 먼저 보여준다. 복원 뒤 Task를 열 수 있게 하고 영구 삭제는 별도 동작으로 구분한다. |

계획·주간 리뷰·집중·인사이트는 코드에 남아 있는 기능으로, 현행 화면 진입 범위에서 제외된다. 구현 범위를 잡을 때 활성 경로 기준으로 확인한다. [저장소 기능 범위](feature-scope.md)

## 화면 사이에서 맞춰야 할 동작

1. **입력과 이동.** 빠른 입력에 화면 맥락을 넣는다. 오늘은 오늘 예정일, 캘린더는 선택 날짜, 칸반은 프로젝트·열 상태가 기본값이다. 입력 전에 해석된 값이 보이고 사용자가 바꿀 수 있게 한다. Ctrl+K와 기존 해시 URL을 활용해 이동하고, 편집창을 닫으면 출발점의 필터·스크롤·포커스를 복구한다.
2. **날짜와 상태.** Task의 예정일은 작업할 날, 마감일은 기한으로 표기한다. 예를 들어 11월 20일 마감 Task를 오늘로 가져와도 마감일은 20일이다. Task의 진행 상태와 `미계획·예정·언젠가·대기` 조건을 별도 필드로 유지한다. 기존 하루 전환 기준을 적용해 새벽 경계에서 오늘·주간·기한 표기가 맞는지 확인한다.
3. **수정·제거·복구.** 모든 화면에서 같은 Task를 편집한다. 완료·일정 변경·휴지통 이동 뒤 동일한 위치에 처리 결과와 되돌리기를 제공한다. 현재 앱은 삭제·변경·메모 삭제의 알림 경로가 각각 있으므로 표시 규칙을 맞춘다. 서버 실패와 오프라인 대기를 구분하며, 일괄 편집이 일부 실패하면 성공 범위만 갱신한다.
4. **읽기와 조작.** 기존 테마·글꼴·간격 토큰을 활용한다. 오늘은 좁은 읽기 폭, 프로젝트·캘린더는 넓은 작업 폭을 쓰고 페이지마다 주 동작을 하나로 잡는다. 반복 설명보다 제목·그룹·간격으로 구조를 구분한다. 상태는 색과 텍스트로 표시하고, 주요 메뉴를 마우스 호버 없이도 열 수 있게 한다. 빈 화면·검색 결과 없음·연결 실패의 메시지와 복구 동작을 구별한다.

## 구현 순서와 확인 기준

| 순서 | 변경 | 완료 확인 |
| --- | --- | --- |
| 1 | 공통 날짜 표기, 입력 기본값, 작업 메뉴·되돌리기 계약을 정리하고 칸반 카드의 휴지통 이동에 먼저 적용 | 한 Task를 프로젝트에서 제거하면 오늘·캘린더·전체 Todo에도 반영되고 복구하면 돌아온다. 일정 이동 뒤 마감일이 유지된다. |
| 2 | 프로젝트 칸반 배치, 오늘 계획 진입, 전체 Todo의 검색·일괄 도구 정리 | 프로젝트에서 만든 Task를 오늘로 가져와 처리하고, 전체 Todo에서 다시 찾는다. 부모·자식이 있는 Task를 제외하고 연결을 복원한다. |
| 3 | 캘린더 선택 날짜 유지, 메모·낙서장 저장 상태, 설정·휴지통의 복구 흐름 | 월간에서 고른 날짜로 주간을 열고 기존 링크로 돌아간다. 저장 실패 뒤 초안을 복원한다. 휴지통 복원 결과를 확인한다. |

실제 구현에서는 1280·1440·1920px의 데스크톱, 라이트·다크, 키보드 탐색, 모바일 주요 동작을 확인한다. 메모·낙서장 검증은 예시 본문을 사용한다.
