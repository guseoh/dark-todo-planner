# Tern Windows 네이티브 QA

운영 웹 UI는 검증 대상이 아니다. PR의 Rust cargo check는 컴파일을 검증하며 실제 WebView2 렌더링 및 IPC를 보장하지 않는다.

## 자동 네이티브 시작 스모크 (수동 workflow)

`tern-windows-smoke.yml`은 GitHub Windows runner에서 서명 없는 개발용 실행 파일을 생성하고 시작한다. NSIS 패키징 및 릴리스는 하지 않으며, 운영 계정 로그인·D1 변경도 수행하지 않는다. 프로세스 유지와 메인 창의 존재만 검증한다. GitHub runner의 데스크톱 세션 제약으로 실패하면 로컬 설치본 검증을 사용한다.

## 로컬 릴리스 확인

1. GitHub Release의 공식 서명 설치 파일로 업데이트하고 앱 설정에서 실제 설치 버전을 확인한다.
2. 로그인, Today/메모/프로젝트 조회, 변경 사항 저장 및 재시작 후 재조회 확인 (테스트용 항목 사용).
3. 시스템 트레이 열기/숨기기/종료, Ctrl+Shift+K 빠른 입력, 키보드·한글 IME, 밝은/어두운 테마 확인.
4. 오프라인 변경이 재연결 뒤 반영되는지 확인하고 동기화 전에 데이터 삭제 금지.
5. 다음 서명 릴리스가 발견되고 승인 후 설치·재시작되는지 확인한다. 업데이트 확인과 실제 설치 성공은 별도로 기록한다.

서명되지 않은 CI 시작 스모크 산출물은 사용자에게 배포하지 않는다.

## 업데이트와 인증 안정성

- 시작/시간별/트레이/설정 확인은 공통 업데이트 조정자를 사용한다. Rust에서도 동시 실행을 거부한다. 확인한 버전과 실제 설치할 버전이 다르면 다시 확인한다.
- 미동기화 Todo 큐가 남아 있거나 저장소 조회에 실패하면 설치를 거부한다. 메모·낙서장의 복구 초안은 설치/트레이 종료 직전 동기적으로 로컬 저장한다. 저장 실패 또는 진행 중인 API 쓰기는 종료·업데이트를 차단한다. 설치 중 화면 입력 및 신규 IPC 쓰기를 막는다. 강제 종료·전원 손실과 다른 편집 영역은 여전히 보장되지 않는다.
- 인증 응답을 받기 전에 사적 스냅샷을 화면에 표시하지 않는다. 네트워크 오류는 세션 만료와 구분하며 재확인을 제공한다. Windows Credential Manager에 서버 발급 세션 토큰만 저장한다. 재시작하면 해당 토큰을 복원하되 서버의 세션 검증을 다시 통과해야 한다. 비밀번호·평문 파일·WebView 저장소에는 토큰을 쓰지 않는다. 명시 로그아웃 시 저장된 토큰을 먼저 제거하며 저장소 삭제 실패 시 오류를 표시한다. 저장 실패는 메모리 세션으로만 유지하고 실제 로그인 유지 여부는 로컬 QA에서 확인한다.
- 서명 실패/연결 실패/중복 요청 후 다시 확인 및 설치가 가능한지 검증한다. 이전 설치 파일과 공식 Releases 경로를 보존한다. 앱 롤백 시 D1 데이터나 스키마를 되돌리지 않는다.
- Windows PR 검증에서 locked cargo tree로 glib가 대상 그래프에 없는지 확인한다. Linux/BSD용 간접 의존성의 advisory를 해결했다고 간주하거나 경고를 자동으로 dismiss하지 않는다.

## 중복 실행 및 복구

- Windows 로컬 앱 데이터의 OS 파일 잠금을 프로세스 생명주기 동안 유지한다. 두 번째 실행은 종료하며 기존 인스턴스는 트레이에서 열 수 있다. 잠금 파일을 삭제하거나 강제 해제하지 않는다.
- 낙서장 서버 저장 실패 후 online 이벤트에서 현재 내용만 다시 저장하며 메모의 실패한 링크 저장은 기존 ID를 유지한다. 인증 및 업데이트 확인 역시 연결 복구 시 재시도한다.
- `tern-windows-smoke.yml` 수정 PR에서만 추가 시작 검사를 실행하며 일반 PR은 기존 경량 검사를 유지한다. 시작 검사에서 두 번째 프로세스 종료를 확인한다. `native-qa` 라벨을 붙인 네이티브 PR은 Rust 단위 테스트 실행도 가능하다.

## 실제 설치본 완료 기준

- 동일 서명 키의 N → N+1 업데이트 탐지·승인·설치·재시작과 실제 설정 버전을 확인한다.
- 연결 끊김 및 서명 검증 실패 시 기존 앱이 계속 실행되고 재시도 가능해야 한다.
- 동기화되지 않은 Todo가 있으면 업데이트를 막으며, 재로그인/재시작 이후 데이터가 보존되는지 확인한다.
- 재시작 이후 인증 및 백업·복원은 시험 데이터로 별도 확인한다. CI에서 운영 계정을 사용하지 않는다.

IPC GET 취소는 WebView가 응답 대기를 중단하는 의미입니다. Rust 네트워크 요청 자체는 최대 기존 timeout까지 계속될 수 있습니다. 이미 전송한 POST/PUT/PATCH/DELETE는 중단된 것처럼 보고하지 않고 실제 응답을 기다립니다. 네트워크가 끊긴 쓰기 결과는 미확정일 수 있어 자동 재시도 정책은 기존 Todo 멱등성 범위에 한정합니다.
